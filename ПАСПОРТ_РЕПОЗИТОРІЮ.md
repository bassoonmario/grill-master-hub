## 🎯 Опис проекту

**grill-master-hub** — комплексна система управління виробництвом для гриль-фабрики **Grills factory**. PWA додаток для керування складом, завданнями, циклами виробництва та API для роботи з даними.

### Ключові таблиці та нюанси (оновлено 26.06.2026)

**`bot_workshop.cases_components`** — нові колонки (додано 24.06):

- `unit_type VARCHAR(20)` — `'pcs'|'kg'|'roll'|'strip'`
- `conversion_factor NUMERIC(10,4)` — скільки шт в одиниці
- `is_internal BOOLEAN` — true=Матей робить сам, false=їде з пошти

**`bot_workshop.incoming_tasks`** — нові колонки (додано 24.06):

- `component_id INTEGER` — FK→cases_components (для тасок фурнітури)
- `input_qty NUMERIC(10,4)` — кількість в природних одиницях
- `unit_type VARCHAR(20)`, `conversion_factor NUMERIC(10,4)`

**`bot_workshop.daily_shipments`** — `is_written_off` скидається в `true` кроном о 22:00 щодня (будні). Скрипт обробляє ВСІ записи де `false` без фільтра по даті — при ручному запуску є ризик подвійного списання.

**Конвертації `cases_components`:**

|Позиція|unit_type|conversion_factor|
|---|---|---|
|Шуруп 2_10, 2.5_8|kg|25000|
|Резинка (м)|roll|50|
|Ремінець (м)|roll|100|
|Липучка (м)|roll|25|
|Ручка чорна|strip|7|
|Решта|pcs|1|

**`bot_workshop.inventory_checks`** — таблиця інвентаризацій (додано 26.06):

- `id, item_id, table_key, system_qty, actual_qty, delta, checked_at, note`
- Індекс по `(item_id, table_key)`
- `GET /api/admin/inventory/checks/latest` — DISTINCT ON (item_id, table_key), останній запис для кожної позиції
- `POST /api/admin/inventory/check` — зчитує поточний qty, рахує delta, пише запис

**`bot_workshop.history_logs`** — журнал операцій списання (переструктуровано 26.06):

- Нова структура: `session_id UUID, article, component, qty, source, operation`
- Стара структура `(item_id, change_qty, operation_type)` — дропнута, дані не переносились (були тестові)
- `session_id` генерується один раз на початку `run_write_off` — групує всі записи одного запуску

**Логіка write-off (оновлено 25.06):** пріоритет `inventory_finished` → `inventory_cases` + `recipes` → `inventory_operative` (кейс) або `recipes` → `inventory_operative` (не-кейс). `recipes_cases`/`cases_components` в write-off НЕ використовуються.
